# 송영MAP

주간보호센터 스마트 송영경로 설계하는 웹사이트. 센터와 어르신 주소를 넣으면
센터 → 어르신 여러 명 → 센터로 돌아오는 방문 순서를 찾아 준다.

## 추천 경로

같은 사람들을 같은 차로 태워도 도는 순서를 바꾸면 성격이 달라진다.
그래서 한 가지 답만 주지 않고 최대 세 가지를 내놓고 이유를 적는다.
결과가 같으면 겹치는 것은 빼고 보여 준다.

**1. 최단 거리** — 총 주행거리가 가장 짧다. 기름값과 차량 부담이 가장 적다.

**2. 탑승 시간 최소** — 어르신이 차에 앉아 계시는 시간의 합이 가장 짧다.
한 구간을 달릴 때 이미 타신 분들이 모두 그 시간을 함께 보내므로,
구간 거리에 그때까지 태운 인원수를 곱해 더한 값을 최소화한다.
주행거리는 더 길어질 수 있다.

**3. 역순** — 1번과 같은 길을 반대로 돈다.
거리는 두 지점 사이가 서로 같으므로 뒤집어도 **주행거리와 총 소요 시간이
완전히 같다.** 바뀌는 것은 누가 먼저 타고 누가 나중에 타느냐다.
가장 먼저 타는 분이 가장 오래 앉아 계시므로, 특정 어르신을 일찍
모셔야 하거나 반대로 오래 태우지 않아야 할 때 쓴다.

## 폴더 구성

```
index.html          화면 전체 (프레임워크 없음)
admin.html          관리자 전용: 이용자 이메일 등록/삭제
api/local.js        카카오 로컬 API 프록시 (주소 검색)
api/mapkey.js       카카오맵 자바스크립트 키 전달 (지도 표시)
api/directions.js   카카오모빌리티 길찾기 프록시 (실제 도로 경로)
api/auth.js         이용 신청(로그인) — 등록된 이메일인지 확인
api/admin-users.js  관리자 화면이 부르는 이용자 등록/삭제 창구
api/_auth.js        위 인증 관련 코드가 함께 쓰는 도구 (라우트 아님)
package.json        서버리스 함수를 ESM 으로 읽게 하는 설정
```

## 이용자 관리 (관리자가 등록한 사람만 사용)

이 앱은 누구나 열 수 있는 주소가 아니라, **관리자가 등록한 이메일을
가진 사람만** 쓸 수 있다. 회원가입이나 비밀번호는 없다 — 처음 열면
이메일 주소를 입력하는 화면이 뜨고, 그 이메일이 등록돼 있고 아직
기간이 남아 있으면 통과된다. 한 번 통과하면 같은 브라우저에서는
1년 동안(또는 등록 기간이 그보다 짧으면 그때까지) 다시 입력하지
않아도 된다.

> 비밀번호 없이 이메일만으로 통과되는 방식이라, 그 이메일 주소를
> 아는 사람이면 원칙적으로 흉내 낼 수 있다. 외부에 공개하는 서비스가
> 아니라 소속 직원끼리 쓰는 내부 도구를 전제로 한 가벼운 방식이다.
> 더 강한 보안이 필요하면 이메일 인증코드 발송 방식으로 바꿀 수 있다.

### 관리자 화면

`https://<배포 주소>/admin.html` 로 들어가 `ADMIN_PASSWORD` 로 설정한
비밀번호를 입력하면 이용자를 등록·삭제할 수 있다. 등록할 때 기간(년)을
지정할 수 있고, 기본값은 1년이다. 이미 등록된 이메일을 다시 등록하면
만료일이 그만큼 늘어난다(연장).

이 화면 링크는 직원에게 공유하지 않는다. URL 을 안다고 바로 들어가지는
못하지만(비밀번호가 필요하다), 비밀번호는 계산할 필요 없이 그 자체로
문(관리자인지 아닌지)의 전부이므로 조심히 다룬다.

### 필요한 환경변수

| 환경변수 | 쓰임 |
|---|---|
| `AUTH_SECRET` | 이용자 쿠키에 서명할 임의의 긴 문자열. 아무 값이나 되지만, 한 번 정하면 바꾸지 않는다(바꾸면 모든 이용자가 다시 로그인해야 한다) |
| `ADMIN_PASSWORD` | 관리자 화면(`/admin.html`) 비밀번호 |
| `EDGE_CONFIG` | 이용자 명단을 읽어 오는 연결 문자열. 버셀 프로젝트에 Edge Config 를 연결하면 자동으로 채워진다 |
| `EDGE_CONFIG_ID` | 명단을 쓰기(등록/삭제) 위해 필요. Edge Config 화면에서 `ecfg_...` 형태의 아이디를 복사 |
| `VERCEL_API_TOKEN` | 명단 쓰기에 필요. 버셀 계정 설정 → Tokens 에서 발급 |
| `VERCEL_TEAM_ID` | 프로젝트가 팀(조직) 소속일 때만 필요 |

### 설정 절차 (버셀 대시보드)

1. **Storage → Create Database → Edge Config** 로 이 프로젝트에 Edge Config 를
   하나 만들어 연결한다. 연결하면 `EDGE_CONFIG` 환경변수가 자동으로 생긴다.
2. 그 Edge Config 화면에서 아이디(`ecfg_...`)를 복사해 `EDGE_CONFIG_ID` 로 넣는다.
3. 버셀 계정 **Settings → Tokens** 에서 토큰을 발급해 `VERCEL_API_TOKEN` 으로 넣는다.
   (이 토큰이 있으면 명단을 등록/삭제할 수 있으니, 카카오 REST 키와 마찬가지로
   저장소에 커밋하지 않는다.)
4. `AUTH_SECRET` 에 아무 문자열이나(예: 32자리 임의 문자열) 넣는다.
5. `ADMIN_PASSWORD` 에 관리자 비밀번호를 정해 넣는다.
6. 다시 배포한다. `/admin.html` 에서 첫 이용자를 등록하면 바로 쓸 수 있다.

Edge Config 를 아직 연결하지 않았거나 위 환경변수가 빠져 있으면, 이용
신청 화면에서 "이용 여부를 확인하지 못했습니다"라는 안내와 함께 앱이
막힌 채로 배포된다 — 설정이 안 된 채로 누구에게나 열리는 사고보다
안전한 쪽을 기본값으로 삼았다.

## 화면 구성

지도가 화면을 채우고 왼쪽에 입력 패널이 붙는다.
좁은 화면에서는 지도가 위, 입력이 아래로 쌓인다.

맨 위에는 **등원 송영 / 하원 송영** 전환 버튼이 있고, 왼쪽 패널은
매일 쓰는 순서대로 4단계 탭으로 나뉜다.

1. **센터 정보** — 센터 이름·주소, 차량 대수·차량당 정원, 평균 속도나
   도로 보정 계수 같은 세부 설정(고급 설정 안에 접혀 있음).
2. **어르신 관리** — 한 번 등록해 두면 매일 다시 입력할 필요가 없는
   어르신 주소록. 등록/수정/삭제와 전체 삭제, 이름·주소를 여러 줄로
   붙여 넣는 일괄 등록을 지원한다.
3. **오늘 송영** — 주소록에서 오늘 태울 분만 체크한다. 전체 선택/전체
   해제 버튼이 있고, 사람마다 어느 차에 고정할지(자동배정/1호차 고정/…)
   고를 수 있다.
4. **송영 결과** — 계산을 누르면 차량별로 나뉜 카드가 뜬다.

- 결과 목록의 한 줄을 누르면 지도가 그 지점으로 이동한다.
- 등록한 어르신 주소록, 오늘 체크한 명단, 센터 정보와 세부 설정은
  브라우저에 저장되어 다시 열어도 그대로 남아 있다.
  (저장은 그 브라우저 안에만 있고 서버로 올라가지 않는다.)

## 지도

카카오맵을 먼저 쓴다. 카카오맵 키가 없거나 못 불러오면
OpenStreetMap 으로 내려간다. 지금 어느 쪽을 쓰는지는
제목 아래 줄에 나온다.

| 화면에 뜨는 말 | 뜻 |
|---|---|
| `카카오맵 사용 중` | 정상 |
| `... 카카오맵 키가 설정되지 않았습니다` | `KAKAO_JS_KEY` 환경변수가 없다 |
| `... 카카오맵을 불러오지 못했습니다` | 키는 있으나 도메인 등록이 안 됐을 가능성이 크다 |
| `지도를 표시하지 못했습니다` | 둘 다 실패. 계산과 인쇄는 그대로 된다 |

OpenStreetMap 은 대비책이라, 카카오맵이 뜨면 아예 내려받지 않는다.

## 실제 도로 경로

방문 순서가 정해지면, 그 순서 그대로 카카오모빌리티 길찾기(자동차)에
물어 실제 도로를 따라가는 선과 실제 주행거리로 바꾼다. 계산을 누른
직후에는 우선 직선거리 추정으로 빠르게 보여 주고, 실제 경로를 받아
오면 화면과 지도가 자동으로 그 값으로 바뀐다.

- 별도의 키는 필요 없다. 주소 검색과 같은 `KAKAO_REST_KEY` 를 쓴다.
  다만 카카오 개발자 사이트에서 그 앱에 **모빌리티 - 길찾기** 상품을
  추가로 신청해야 동작한다.
- 신청하지 않았거나, 그날따라 카카오모빌리티가 응답하지 않거나,
  경유지가 너무 많으면(28명 초과) 화면은 조용히 직선거리 추정으로
  돌아간다. 오류가 나거나 계산이 멈추지 않는다.
- 안내 문구로 지금 어느 쪽인지 알 수 있다: `거리는 카카오모빌리티
  실제 도로 경로를 기준으로 잰 값입니다` 라고 뜨면 실제 도로 기준이고,
  `거리는 두 지점의 직선거리에 보정 계수 ...` 라고 뜨면 추정값이다.
- 방문 순서를 정하는 계산 자체(어느 차에 누굴 태우고 어떤 순서로
  도는지)는 여전히 직선거리 기준의 빠른 방식을 그대로 쓴다. 실제
  도로 경로는 순서가 정해진 뒤, 화면에 보여 줄 거리·경로 좌표만
  실제 값으로 바꾸는 데 쓴다.

## 시간대별 도로 사정

송영은 매일 같은 시각에 나가므로, 그 시간대에 길이 어떤지가 실제
소요 시간을 좌우한다. `세부 설정`의 **출발 시각의 도로 사정 반영**을
켜 두면 출발 시각에 따라 속도를 조정한다.

| 시간대 | 속도 |
|---|---|
| 07:00–09:00 출근 정체 | 0.72배 |
| 09:00–12:00 오전 | 그대로 |
| 12:00–13:30 점심 | 0.88배 |
| 13:30–17:00 오후 | 그대로 |
| 17:00–19:00 퇴근 정체 | 0.68배 |
| 19:00–22:00 저녁 | 1.05배 |
| 그 밖 (밤·새벽) | 1.15배 |

**한 번 정해 놓고 끝이 아니라 구간마다 다시 잰다.** 08:30 에 나가면
앞 구간은 정체로, 09시를 넘긴 뒤 구간은 원활한 속도로 계산한다.

그래서 `평균 속도`는 **길이 원활할 때 기준**으로 적어야 한다.
막히는 시간을 감안해 미리 낮춰 적으면 두 번 깎인다.

배정을 고르는 동안(어느 차에 누구를 태울지)은 순서가 아직 없으므로
출발 시각의 도로 사정 하나로만 어림잡고, 순서가 정해진 뒤 구간별로
다시 잰다.

이 값들은 실측이 아니라 통상적인 도심 기준이다. 지역에 따라 다를 수
있으니, 실제와 차이가 크면 `평균 속도`로 맞추면 된다.
소요 시간은 이 시간대 배율로 어림잡는다. 실제 도로 경로(위 항목)를
받아 왔다면 거리만 실제 값으로 바뀌고, 그 위에 같은 시간대 배율을
적용해 시간을 잰다 — 실시간 정체 예측까지 반영하는 것은 아니다.

## 카카오맵으로 길안내 받기

결과의 각 구간에 `길안내` 단추가 있다. 누르면 그 구간의 카카오맵
길찾기가 열린다. 어르신 한 분을 태우고 다음 구간 안내를 받는
식으로 쓴다.

전체 코스를 한 번에 카카오맵으로 넘기지는 못한다. 카카오맵 링크가
출발지와 도착지 한 쌍만 받고 경유지 여러 개를 받지 않기 때문이다.
그래서 구간별로 나눠 연다.

## 인쇄

결과 화면의 인쇄 버튼을 누르면 지도와 버튼은 빠지고
센터 이름, 날짜, 인원, 총 거리, 방문 순서만 종이에 담긴다.
운행 담당자에게 건네는 용도로 쓸 수 있다.

카카오 키는 `index.html`에 없다. 서버 환경변수에만 두고,
브라우저는 같은 도메인의 `/api/local` 만 호출한다.

## 배포 절차

### 1. 폴더를 준비한다

이 폴더(`index.html`과 `api` 가 들어 있는 폴더)를 그대로 쓴다.

### 2. 버셀에 올린다

터미널에서 이 폴더로 이동한 뒤:

```
npx vercel
```

카카오 계정이 아니라 버셀 계정으로 로그인하라는 안내가 나온다.
질문은 전부 기본값(엔터)으로 넘기면 된다.

GitHub를 쓴다면 이 폴더를 저장소에 올리고
vercel.com → Add New → Project → 저장소 선택으로도 된다.

### 3. 카카오 키를 환경변수로 넣는다

카카오 키는 두 가지를 쓰고, 다루는 방법이 서로 다르다.
카카오 개발자 사이트의 같은 앱 안, '플랫폼 키' 화면에 나란히 있다.

| 키 | 쓰임 | 어디에 두나 |
|---|---|---|
| **REST API 키** | 주소 검색, 실제 도로 경로 | 버셀 환경변수 `KAKAO_REST_KEY` 에만 |
| **JavaScript 키** | 지도 표시 | `index.html` 에 적혀 있음 |

> **REST 키는 이 저장소에 절대 커밋하지 않는다.**
> 저장소가 공개 상태라 커밋하면 즉시 외부에 노출되고,
> 이 키는 도메인 제한이 없어 누구나 가져다 쓸 수 있다.
> 적는 곳은 버셀 설정 화면 단 한 곳이다.

> 실제 도로 경로까지 쓰려면 카카오 개발자 사이트에서 같은 앱에
> **모빌리티 - 길찾기** 상품을 추가로 신청해야 한다. 신청하지
> 않아도 앱은 그대로 동작하고, 거리는 직선거리 추정으로 나온다.

버셀 대시보드 → 해당 프로젝트 → Settings → Environment Variables
에서 `KAKAO_REST_KEY` 를 넣고, Production, Preview, Development
세 곳 모두 체크한다.

JavaScript 키는 사정이 다르다. 지도 SDK 를 브라우저가 직접
불러오는 구조라 이 키는 어차피 화면 소스에 드러난다. 그래서
`index.html` 에 적어 두고, 아래의 도메인 등록으로 막는다.
카카오 공식 문서도 같은 방식을 안내한다.

키를 코드에서 바꾸기 싫으면 버셀에 `KAKAO_JS_KEY` 환경변수를
넣으면 된다. 그 값이 `index.html` 에 적힌 것보다 우선한다.

### 카카오맵을 쓰려면 도메인 등록이 필요하다

JavaScript 키는 등록된 도메인에서만 동작한다. 이것이 키를 감추는
대신 쓰는 보호 장치이므로, 등록하지 않으면 키가 코드에 있어도
지도가 뜨지 않는다.

카카오 개발자 사이트 → 내 애플리케이션 → 앱 설정
→ **플랫폼 키** → **JavaScript 키** → **JavaScript SDK 도메인**
에 배포 주소를 넣는다.

```
https://<프로젝트이름>.vercel.app
```

미리보기 주소까지 쓰려면 그 주소도 함께 넣는다.
등록하지 않으면 지도가 OpenStreetMap 으로 내려간다.

> 헷갈리기 쉬운 곳이 하나 있다.
> **제품 링크 관리**의 '웹 도메인'은 여기가 아니다.
> 그쪽은 카카오톡 공유·메시지의 링크 이동용이라,
> 거기 넣어도 지도는 뜨지 않는다.

### 4. 다시 배포한다

환경변수는 새로 배포해야 반영된다.

```
npx vercel --prod
```

대시보드의 Deployments → 맨 위 항목 → Redeploy 를 눌러도 된다.

## 확인 방법

배포된 주소를 열었을 때 제목 아래에
`카카오 주소 검색 사용 중` 이라고 뜨면 정상이다.

`공개 지도 데이터로 주소를 찾습니다` 라고 뜨면 환경변수가 안 잡힌 것이다.
Settings의 변수 이름 철자와 재배포 여부를 확인한다.
이 상태에서도 앱은 동작한다. 국내 주소 정확도만 떨어진다.

## 방문자는 어떻게 쓰나

방문자는 카카오 키를 준비할 필요가 없다. 주소를 검색하면
브라우저가 같은 도메인의 `/api/local` 을 부르고, 서버가 등록된
`KAKAO_REST_KEY` 로 카카오에 대신 물어본다. 키는 브라우저로
내려가지 않으므로 방문자가 키를 알아낼 수는 없다.

배포 주소만 알려 주면 바로 쓸 수 있다. 로그인도 설치도 없다.

### 방문자가 들어와도 화면이 안 뜬다면

버셀의 배포 보호 기능이 켜져 있으면 링크를 받은 사람에게
로그인 화면이 뜬다. 다음을 끈다.

버셀 대시보드 → Settings → **Deployment Protection**
→ Vercel Authentication → **Disabled**

### 할당량 보호

공개된 주소라 누구나 `/api/local` 을 직접 부를 수 있다.
카카오 호출이 과하게 늘어나지 않도록 두 가지를 둔다.

- 같은 IP 는 1분에 60번까지만 호출할 수 있다. 넘으면 429 를 준다.
  사람이 손으로 주소를 넣는 속도로는 걸리지 않는다.
- 한 번 찾은 주소는 하루 동안 캐시에서 돌려준다.
  여러 방문자가 같은 주소를 넣어도 카카오는 한 번만 부른다.

제한은 함수 인스턴스마다 따로 세므로 정확한 총량 상한은 아니다.
대량 호출을 늦추는 장치로 보면 된다. 사용량은 카카오 개발자
사이트에서 확인할 수 있다.

## 로컬에서 돌려볼 때

`.env.example` 을 `.env.local` 로 복사하고 값을 채운 뒤:

```
cp .env.example .env.local
# .env.local 을 열어 KAKAO_REST_KEY 값을 채운다
npx vercel dev
```

`.env.local` 은 `.gitignore` 에 걸려 있어 커밋되지 않는다.

## 키가 노출됐을 때

키를 실수로 커밋했거나 외부에 보냈다면 카카오 개발자 사이트에서
REST API 키를 재발급받는다. 기존 키는 그 즉시 무효가 된다.
재발급 후에는 아래 절차로 버셀 값만 바꾸면 된다.

## 키를 바꿀 때

카카오 개발자 사이트에서 키를 재발급받은 뒤,
버셀 Settings 의 해당 값을 바꾸고 재배포하면 된다.
`index.html` 은 손댈 일이 없다.

JavaScript 키는 브라우저에 드러나는 것이 정상이다.
감추는 대신 위의 도메인 등록으로 막는다.
REST 키는 서버 밖으로 나가지 않는다.

## 차량 여러 대로 나누기

차량 대수를 2대 이상으로 두면 인원을 나눠 배정한다.
차량당 정원을 넘지 않고, 인원이 정원 합계를 넘으면 계산 대신 알려 준다.

배정의 기준은 **총 주행거리가 아니라 가장 오래 걸리는 차의 시간**이다.
어르신이 차 안에 오래 앉아 계시지 않는 쪽이 센터에서 실제로
중요하기 때문이다. 그래서 여러 대로 나누면 총 주행거리는 오히려
늘어날 수 있고, 대신 마지막 어르신이 센터에 닿는 시각이 당겨진다.

나누는 방법은 이렇다.

1. 센터를 중심으로 방위각 순서로 세워, 같은 방향에 사는 분들이
   한 차에 묶이도록 자른다. 어느 방향에서 자르기 시작하느냐에 따라
   결과가 달라지므로 모든 시작점을 돌려 보고 제일 나은 것을 고른다.
2. 그 배정에서 한 명씩 다른 차로 옮기거나 두 명을 맞바꿔 보면서
   더 나아지면 받아들인다. 나아지지 않을 때까지 반복한다.
3. 배정이 정해지면 차량마다 방문 순서를 따로 푼다.

지도에서는 차량마다 색이 다르고, 결과와 인쇄물도 차량별로 나뉜다.

### 차량 고정

**오늘 송영** 탭에서 사람마다 배정을 `자동배정` 대신 `1호차 고정`,
`2호차 고정`처럼 특정 차로 못박을 수 있다. 고정된 분은 항상 그 차에
타고, 나머지 분들만 자동으로 배정된다. 고정된 인원이 그 차의 정원을
넘으면 계산 대신 몇 호차에 몇 명이 초과됐는지 알려 준다.

## 어르신 주소록

**어르신 관리** 탭에 한 번 등록해 두면 다음부터는 매일 새로 입력할
필요가 없다. 등록·수정 화면에는 이름, 주소, 기본으로 탈 차량, 메모만
있다. **생년월일, 장기요양등급, 전화번호는 아예 받지 않는다** — 송영
경로를 짜는 데 필요한 최소 정보만 다루기 위해서다.

- 이름과 주소를 여러 줄로 붙여 넣어 한 번에 등록할 수 있다
  (`이름, 주소` 형식, 줄마다 한 명).
- 저장은 브라우저의 IndexedDB 에 하므로 새로고침·재접속에도 남는다.
- 어르신 관리 화면에서 전체 삭제를 누르면 주소록을 통째로 지울 수 있다.

## 등원 / 하원

화면 맨 위의 **등원 송영 / 하원 송영** 버튼으로 전환한다. 둘 다
"센터 → 어르신들 → 센터"로 도는 모양은 같지만 서로 다른 상황이라
독립적으로 다룬다.

- 오늘 체크한 명단, 차량 고정, 출발 시각을 등원/하원 각각 따로
  저장하고 기억한다. 등원에서 체크한 사람이 하원에도 자동으로
  옮겨지지 않는다.
- 하원은 등원 경로를 단순히 거꾸로 돈 것이 아니라 별도로 다시
  최적화한다. 등원은 **태우는 시점**이 이를수록 그 어르신이 차에
  오래 앉아 계시고, 하원은 **내리는 시점**이 늦을수록 오래 앉아
  계시므로, 같은 순서라도 계산 기준이 서로 반대다.

## 계산 방식

- 어르신 14명까지는 가능한 모든 순서를 비교해 최단 경로를 찾는다 (Held-Karp).
- 15명 이상은 최근접 이웃 + 2-opt 근사 계산으로 넘어가고, 결과에 그 사실을 표시한다.
- 거리는 두 지점의 직선거리에 도로 보정 계수를 곱한 추정값이다.
  실제 도로와 교통 상황은 반영되지 않는다.
